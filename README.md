# keenetic_domains

Доменные списки маршрутизации роутера Keenetic, разложенные по файлам и
пригодные к импорту в [awg-manager](https://github.com/hoaxisr/awg-manager).

Источник истины — конфигурация роутера (`object-group fqdn` + правила
`route object-group … <интерфейс>` в блоке `dns-proxy`). Этот репозиторий
делает её читаемой, версионируемой и пригодной к подписке по ссылке.

## Раскладка

| Что | Где |
|---|---|
| списки доменов | `lists/<имя>.txt` — один домен в строке, комментарии через `#` |
| маршруты для импорта | `routes.json` — ссылается на списки по URL (подписки) |
| автономный вариант | `routes-inline.json` — домены внутри файла, без ссылок |
| инструменты | `tools/` |
| дамп конфига роутера | `.local/` — **не версионируется**, там приватные ключи |

Имя маршрута в `routes.json` — это `description` группы с роутера, то есть
человекочитаемое название сохраняется. Имя файла — транслитерация того же
описания.

## Обновление списков

```sh
sh tools/fetch-config.sh                       # снять running-config в .local/
python3 tools/build.py \
    --config .local/running-config.txt \
    --base-url https://raw.githubusercontent.com/<user>/keenetic_domains/main
git add -A && git commit -m "обновление списков" && git push
```

Переменные `HOST`, `PORT`, `LOGIN` у `fetch-config.sh` переопределяются;
умолчание — `root@192.168.2.1:222`.

## Списки с нескольких роутеров

`build.py` пересобирает репозиторий из одного роутера с нуля. Чтобы долить
группы с другого роутера, не теряя уже собранного:

```sh
sh tools/fetch-config.sh .local/other-config.txt   # HOST/PORT другого роутера
python3 tools/merge.py --config .local/other-config.txt --label Upstroy \
    --base-url https://raw.githubusercontent.com/<user>/keenetic_domains/main
```

`merge.py` сопоставляет группы со списками по имени (копии awg-manager с
суффиксом `_p1` сводятся к исходному списку) и по пересечению доменов, дописывает
только недостающее, заводит новые списки и пересобирает `routes*.json`.

Как Keenetic сопоставляет домены — и почему списки чистятся:

* запись группы ловит любое имя, которое **заканчивается** на неё, причём по
  строке, а не по границе домена: `acebook.com` ловит `facebook.com`,
  `i.org` — `pypi.org`, `x.com` — `netflix.com`. Короткие записи затягивают
  в туннель чужие сайты;
* поэтому в списке не держится поддомен, если есть его родитель
  (`www.viber.com` при `viber.com`), а домен, уже покрытый другим списком,
  не добавляется повторно;
* опечатки и подделки под бренды (`faceboook.com`,
  `achat-followers-instagram.com`) отбрасываются — сервисам они не нужны;
* `exclude.txt` — домены, которые не попадают ни в один список (например,
  счётчики Яндекса: к ним всегда напрямую);
* `instagram`, `facebook`, `meta` собраны вручную из корневых доменов и не
  доливаются: группы роутеров `instagram_*`, `meta_*` сводятся к ним. Прежние
  `instagram-1/2` и `meta-1/2` (сотни доменов, включая `akamaihd.net`,
  который заворачивал в туннель весь CDN Akamai) удалены — их маршруты в
  awg-manager нужно заменить на новые, переимпортировав `routes.json`.

## Импорт в awg-manager

Маршрутизация → импорт → `routes.json`. Туннель для каждого маршрута
выбирается при импорте, в самом файле его нет.

Формат подписки проверен по исходникам awg-manager: по ссылке ожидается
простой текст — один домен или CIDR в строке, комментарии через `#`,
допустимы теги вида `geosite:TELEGRAM`. Строки с пробелами и `*` отвергаются.

Подсети из подписки (`149.154.160.0/20` в `telegram.txt`) awg-manager кладёт
в группу при обновлении списков, а не при импорте: сразу после импорта в
группе только домены, и приложение Telegram, которое ходит к серверам по IP,
идёт мимо туннеля. После импорта нажмите «Обновить» у списков. Если подсеть
уже есть в другом списке, дубль в подписке отбрасывается — это нормально.

Если подписки по ссылке в вашей сборке не заработают, импортируйте
`routes-inline.json` — он самодостаточен, но требует переимпорта при каждом
изменении списков.

## Важное

Подписки тянутся по `raw.githubusercontent.com` **без авторизации**, поэтому
репозиторий должен быть публичным. Публичный репозиторий означает, что список
сервисов, которые вы заворачиваете в туннель, виден всем. Приватный вариант —
держать `routes-inline.json` и переимпортировать руками.

Дамп конфигурации роутера в `.local/` содержит приватные ключи WireGuard.
Каталог перечислен в `.gitignore`; не выносите его оттуда.
